Stage 06: Create backlog & specs

What you are responsible for

You turn the approved plan into tasks for people and agents. Your judgement matters: a task that looks simple may involve code agents often get wrong, while a complex task may be broken into smaller pieces they can handle well.

tasks.md

Does every requirement in scope have a task and a way to check it? Is any unrequested work included?

Dependencies

Is it clear which tasks depend on others? Does frontend work wait for the backend agreement it needs?

Checks and test plans

Are checks before submission and test plans included in tasks.md and planned alongside the work?

Stage 08: Build

What you are responsible for

You review agent output as carefully as work produced by people. You also look for repeated failures. When the same problem keeps happening, consider whether the agent needs more context rather than treating it as a one-off mistake.

Code changes and unit tests

Do they match approved tasks, follow the architecture and standards, and avoid unrequested changes?

Checks

Do the relevant checks pass? Do the records show which commands were run and their results?

Stage 10: Release

What you are responsible for

You decide whether the final codebase is ready to release. The FDA has already decided whether the quality and security evidence is strong enough. Your focus is on whether the work is complete, can be traced back to its requirements, and can be safely undone if needed.

Approval to build

Is the release candidate complete, numbered with a version, and made up only of approved and reviewed work?

Traceability

Can each requirement be followed through the specification, task, code and test?

Deployment settings and rollback

Are the right controls in place for each environment? Has someone confirmed that the release can be safely undone in production?

These are the agents you'll most likely work with:

A.8

Technical Specifier

Analyses a draft specification, identifies ambiguous requirements, missing decisions and conflicting assumptions, and generates a prioritised list of questions for the right role to resolve.
A.9

Implementation Planner

Breaks an approved specification into a sequenced task list with dependencies, acceptance criteria, pre-submit checks and test plans ready for FDE review.
A.10

Implementation Builder

Executes individual tasks from tasks.md — writing code, unit tests and verification records — and submits output for FDE code review.

Code Review

Reviews agent-generated code and unit tests against the approved tasks, specification, architecture and standards. Raises failures, gaps and architectural concerns for the engineer to resolve before the pull request is approved.
A.13

Azure-Deploy

Executes the deployment pipeline against the approved release candidate, applies environment configuration, and confirms rollback readiness for FDE sign-off.
