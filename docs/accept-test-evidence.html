What are you reviewing?

You are reviewing the output of two agents. The API Testing agent (API Tester in the pilot steps) writes its evidence to output/<RUN_ID>/api-tests/attempt-<n>/, and the Functional Testing agent (Functional Automation Test in the pilot steps) writes to output/<RUN_ID>/functional-tests/attempt-<n>/.

The Quality Engineer reviews coverage and results and retains the quality decision. The agent produces evidence, but it does not decide whether that evidence is good enough.

Before reading any results, check which of three outcomes you are looking at, because each one is judged differently.

  • Executed: Tests ran, and every in scope API or UI behaviour is reported as tested, blocked or skipped with a reason.
  • Not applicable: The spec declares API In Scope: NO or UI In Scope: NO, and the report records that evidence with zero APIs, components and cases.
  • Blocked: The spec was missing, did not declare scope, or did not give enough detail to identify what to test. The agent should stop rather than substitute endpoints or screens of its own.

When the output is weak

Do not accept thin evidence on the basis that the tests are green. Passing tests only matter if they test the right things, so send gaps back to the agent with specific corrections and have it run again. Each rerun creates a new attempt folder, which keeps the history honest.

The agent must not change application code to make tests pass. If a test fails because of a real defect, the fix goes back through implementation and code review, not through the test agent. If it fails because of contract drift, the FDE and Application Engineer need to decide whether the code or the contract is wrong.

If the report is blocked or the scope declaration is missing, the fix belongs upstream in spec.md, not in the test run.

Handoff

Once you have accepted the evidence, the Quality & Security gate (FDA) comes next, followed by release readiness (FDE) in Build / Ship. In the pilot sequence the API Tester is reviewed first, then Functional Automation Test starts manually with the same RUN_ID, and then the Quality Tester starts manually after that.
