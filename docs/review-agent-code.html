What are you reviewing

You are reviewing the output of the Implementation Builder (called Implementation Builder in the pilot steps). That means source code changes and unit tests, plus the implementation and verification evidence under output/<RUN_ID>/implement/.

Review it against the approved tasks.md, the specification and the project standards, not against how you would have written it yourself. The Application Engineer is accountable for implementation and pull request quality, and the FDE holds the code review gate.

When the output is weak

Resist the urge to quietly rewrite it. Start by diagnosing what context, architectural rule or repository pattern the agent missed, then correct the instruction or the context and have it revise. That way the fix is repeatable and a one off correction becomes a lesson for the next run.

If the agent keeps failing on the same code path, stop retrying. Some tasks look simple but touch code that agents consistently mishandle, and these should go back to human implementation or a hybrid approach. That call belongs to the FDE. Record recurring failures and context gaps so the shared context and ways of working improve.

Handoff

After human review, the API Tester starts manually as the next stage, using the same RUN_ID and the approved API contract artefacts, once the backend is available in an authorised test environment. Functional Automation Test follows, with API results reviewed first where the increment includes backend APIs.
