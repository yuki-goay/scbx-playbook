# Frame the problem

You have evidences, insights, needs, journey maps and a picture of the current state. What's next? 

The missing piece is a statement that brings everything together — a clear description of the problem the whole team can agree on, and a vision of what things should look like instead. This capability closes discovery and opens everything that follows. An agreed problem statement and shared vision grounds your project and keeps it on track 

---

## Key artefacts

| Activity                                                                                                       | UX artefact                  | When it is worth doing                                                       |
| -------------------------------------------------------------------------------------------------------------- | ---------------------------- | ---------------------------------------------------------------------------- |
| Draft problem statement candidates from the evidence — not from the original brief                             | Problem statement candidates | Every time. Multiple candidates expose where the team's framing might differ |
| Facilitate a shared vision session: what should the experience look and feel like when the problem is resolved | Shared vision                | Every time. The vision is what design decisions are measured against         |


---

## What can agents do?

**AG-02 Research Synthesis** drafts candidate problem statements from filed evidence with citations, and collects and deduplicates vision inputs after the session in preparation for write-up.

**AG-04 Design Organiser** formats the agreed problem statement and shared vision into a shareable document.

Neither agent chooses between candidates or writes a problem statement without evidence.

---

> 💡 **Tips**
>
> **A statement everyone agrees with immediately is probably too vague.** A good problem statement makes a specific claim that can be tested.
>
> **The shared vision is not a list of features.** It is a description of what the experience feels like from the user's side when the problem is resolved.
>
