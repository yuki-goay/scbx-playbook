Proposal Design the detailed screens

You have the information architecture, the experience principles and the design language. Everything you need to design actual screens is in place. This is where you do the work: screen by screen, state by state, interaction by interaction, with real content.

Eventually, you get high-fidelity screens carrying real content, all states designed and interactions specified, and a clickable prototype linking the key flows.

Key artefacts

Activity UX artefact When it is worth doing
Design each screen from the sitemap and screen inventory, using components from the design language, working through the user journey in order Hi-fi screens Always
Use realistic content: the actual labels, headings and messages users will see, not placeholder text Hi-fi screens (with real content) Always, from the first screen
Log each design decision with a reason, as well as interaction annotations for developers Design handover log Always

What can agents do?

AG-04 Design Organiser assembles screens from approved design language components and the sitemap, maintains the screen inventory, links screens into a prototype from the flow diagrams, and logs design decisions.

AG-01 Evidence Librarian logs design decisions and their rationale, and links each decision to the evidence or principle that supports it.

Neither agent invents a screen not in the inventory, makes a design decision, or uses placeholder text where real content has been supplied.

💡 Tips

Iterate in small, single-step batches. Break feedback down. Fix one component, modal, or layout state at a time rather than asking the AI to "fix everything" in one massive prompt.

Where to go next: Check and test the design. It runs a principle check and usability testing against these screens.
